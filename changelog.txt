== Changelog ==

Every change to WP Plugin Starter. readme.txt lists the latest version in short.

= Unreleased =
* Developers: scripts/rename-plugin.sh takes plugin names with quotes, $ and & (such as Owner's "Best" Plugin): the new name is escaped for where it lands (PHP strings, JSON, XML), and the renamed PHP is checked with php -l. Names with / \ < > % or control characters, and URLs with quotes or \, are refused before any file changes. scripts/sync-core.sh escapes the same way. scripts/replaced-plugins.php quotes the name in its README pattern. README.md's languages badge has a line of its own. Nothing changes for users.
* Developers: README.md shows badges on GitHub (CI, SonarCloud, Codacy, CodeFactor, license, latest release) and repository facts (lines of code, languages, dependencies) that .github/workflows/repo-metrics.yml keeps up to date in docs/metrics/. The Read Me tab leaves out the badges block and HTML comments, so it still loads nothing from other sites. scripts/rename-plugin.sh rebuilds the badges for the new repository. Nothing changes for users.
* Fixed: two settings saved at the same moment (two tabs, or two admins) could undo each other, as each save wrote back the whole settings array. A save now holds a short lock while it reads and writes. In a test of 20 saves at once, all 20 are kept (before, 4 to 9 were lost). Uninstalling also removes the lock's row, if one was left.
* Developers: the settings store's sanitize_value() hands each field type to its own small sanitizer, and search() and parse_times() are split into helpers. Values, signatures and option keys are unchanged.
* Developers: scripts/smoke-test.sh keeps its local-only HTTP install command on one line, so SonarCloud reads its NOSONAR note. Nothing changes for users.
* Fixed: a site on the GitHub build could be offered an unrelated WordPress.org plugin that has the same folder name. The GitHub zip's main file now carries an Update URI header on github.com (added by scripts/build-release.sh; the WordPress.org zip has none), and the updater (1.1.0) never takes WordPress.org's answer for such a build.
* Fixed: when GitHub did not answer for a release's requirements (Requires at least, Requires PHP), the release was offered without them for 12 hours; now the check fails and is tried again within the hour.
* Fixed: with a token, the updater took the first zip whose name started with the plugin folder; it now takes only {folder}-{version}.zip, as without a token.
* Fixed: a failed private download address is asked for once per update, its error is kept, and only an https address on a GitHub download host is used.
* Developers: the updater's repeated addresses and version pattern are constants, and its longest methods are split into smaller ones. Its filters and behaviour are unchanged; wpallstars_github_plugins entries may carry 'github_only'.

= 1.0.4 =
* Developers: a top-level setting with 'panel' => true shows its Options panel even without visible child settings, so a feature can render its own controls there (wpstarter_setting_panel), under its switch, instead of in a separate card. Nothing changes for users.
* Developers: scripts/rename-plugin.sh starts the new plugin at version 0.1.0 (--version for another), with the changelogs in README.md, readme.txt and changelog.txt starting again from that version and readme.txt's upgrade notices removed. Before, a new plugin kept the starter's version and changelog.

= 1.0.3 =
* Developers: scripts/rename-plugin.sh takes --description, --author, --author-uri, --plugin-uri, --contributors and --donate, so a plugin made from the starter carries its maker's details instead of the starter's. Each is optional; left out, the starter's value stays. Nothing changes for users.

= 1.0.2 =
* Developers: new Agent docs section in STANDARDS.md. AGENTS.md, which AI agents read in every session, stays a short map: the plugin's names, its own standing rules and one line per doc saying when to read it. Guidance for one kind of task goes in docs/{topic}.md, which never ships. The same pattern fits a small plugin and a large one. scripts/preflight-release.sh warns when AGENTS.md is over 150 lines, names a doc that does not exist, or leaves out one in docs/, and fails if docs/ gets into a release zip. Nothing changes for users.

= 1.0.1 =
* Fix: a select or multi-select setting whose options list fails (its callback throws, for example when another plugin's tables are missing) no longer stops every page after an update. That list is treated as empty, so the settings upgrade finishes; open fields keep their saved values and closed fields fall back to their default.
* Fix: scripts/sync-core.sh in a plugin made from the starter looks for the starter in wp-plugin-starter-template-for-ai-coding next to it again; renaming the plugin had renamed that folder name too, so it only worked with --from.
* Fix: release zips leave out DESIGN.md.
* Fix: the shared GitHub updater (copy 1.0.1) could not update from private repositories on sites where another plugin raises every request's redirection count (HTTP Requests Manager in a blocking mode sets it to 1): GitHub's redirect was followed, so the signed download address was lost and the token went along to the download host. Its requests to GitHub now never follow redirects, whatever other plugins set. Public repositories' release checks had the same problem.
* Fix: the shared GitHub updater's private downloads survive updaters that reset upgrader_pre_download (GPLVault Updater).
* Fix: a replaced plugin's Deactivate link on the settings screen did nothing on sites with Freesoul Deactivate Plugins: it saves its own copy of the active plugins list over any change not made from the Plugins screen. The link now checks the change was saved and, if not, saves just that change. Other code can use the same check: WPStarter_Replaced_Plugins::save_plugin_state().

= 1.0.0 =
* A fresh start, made from the parts every wpallstars plugin needs, taken from plugins in daily use: the settings screen with search, the Read Me tab, features as classes, replaced plugins, the shared GitHub updater, the release and check scripts, CI and the shared rules (STANDARDS.md, DEVELOPMENT.md, RELEASING.md). Earlier versions of this starter are retired; start again from this one.
* New: scripts/rename-plugin.sh gives a copy of the starter its own names, and scripts/sync-core.sh keeps a plugin's core files the same as the starter's.
